# Hosted notification vendors for Cadence

Ticket: GitHub issue #4 "Research: hosted notification vendors for Cadence". Map: issue #3.
Date of research: 2026-11-18.

## Question

Which hosted (non-self-hosted) notification services fit Cadence, a React Router app on SQLite, with students and instructors as audience and three channels: in-app feed, email, and web push? Candidates: Knock, Novu, Courier. Also note any vendor that could replace the Postmark transport in `app/lib/mailer.server.ts`.

## Method and caveats

- Sources are vendor docs, pricing pages, and vendor-owned integration pages, found via search and fetched directly.
- Several pricing and feature pages were summarized by a fetch tool rather than read verbatim. Figures marked "verify" should be checked on the live pricing page before a purchase decision.
- Where a fact was not stated in any primary page we could reach, it is marked "not stated" rather than inferred.
- Self-hosted options (Novu open source, etc.) are out of scope.

## Current Cadence context

`app/lib/mailer.server.ts` defines a `MailTransport` interface with a single `send(email)` method. It has a `postmarkTransport` (Postmark Email API) and an `outboxTransport` (writes JSON to `.outbox/` when no token is set). Any hosted vendor that offers an email provider integration could sit behind this interface, but the vendor's own transport would replace the Postmark call only if the app sends through the vendor API rather than through the vendor's provider config (see the Postmark section below).

## Postmark as a replaceable transport

All three vendors document a Postmark email integration:

- Knock: "Knock integrates with Postmark to send email notifications to your users." Knock sends to Postmark's `outbound` stream by default. Requires a valid `email` property on each recipient. Delivery status only updates for delivered and bounced events, and only with a verified sender signature or domain.
- Novu: Add Postmark under Integrations with the Postmark API key. Supports multiple email providers with an `integrationIdentifier` to pick one. Postmark sender verification: Single Sender or Entire Domain.
- Courier: Enter the Postmark Server API token and a verified From address. Per-message overrides for From address and Postmark Templates API.

Implication for `mailer.server.ts`: any of these vendors could replace the Postmark transport, but the vendor would then own the send, and Postmark would become a provider behind the vendor (a second hop) instead of being called directly. Keeping `postmarkTransport` means the app still owns the send and only the in-app and push channels move. A `MailTransport` backed by a vendor API would be a new implementation of the same `send(email)` interface.

## Recommendation shortlist

1. **Knock.** Closest fit for a student and instructor in-app feed: pre-built React feed with socket real-time, documented Postmark email integration, per-channel/category/workflow preferences, unlimited feed retention by default, and retries with backoff and jitter. Gaps to resolve: web push is only confirmed through FCM, and client-side preference editing is not confirmed.
2. **Courier.** Strong delivery story: about 24 hours of retries and provider failover, Postmark integration with per-message overrides, and a React Inbox with cross-device sync. Gaps: feed and log retention not stated, and web push is via Pusher Beams or FCM, not a confirmed browser provider.

Novu is a weaker fit on the criteria that matter here: channel sends are not retried, there is no failover, and the Free tier keeps only a 24-hour activity feed. Its Postmark and Inbox support is otherwise comparable.

Open questions for the vendor decision:
- Which vendor offers real browser Web Push without a third-party provider (Knock and Courier both route through FCM or Pusher Beams in the docs read)?
- Can preferences be edited from the client in Knock?
- Confirm all Free and Starter tier figures on the live pricing pages.
